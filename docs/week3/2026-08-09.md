# Week 3 — 2026-08-09

Progress report: filtering, machine-learning experiments, Kalman retuning, and
a package refactor.

## What was done

- **Filter suite** (`src/filters/`, `src/kalman/`): moving average, exponential
  smoothing, 1-pole low-pass, and two Kalman variants (`kf` original, `kf2`
  retuned). All share `dt_from_times` so irregular logging intervals are handled
  from the real timestamps.
- **ML experiments** (`src/ml/`): linear regression and random forest, each in
  three framings — `y` on `x`, parametric on sample index `t`, and `t` plus the
  logged motion features.
- **Comparison outputs**: `results/model_comparison.csv` (R² per model × log)
  and `results/movement_comparison.csv` (reach % and jitter % per filter × log).
- **Refactor**: monolithic `grapher.py` split into `filters/`, `kalman/`,
  `ml/`, `analysis/`, `commons/`, `logger/`, `etc/`; data organized under
  `data/raw/<gesture>/`; plots under `plots/`. Conda support (`environment.yml`)
  added alongside Nix.

## Key findings

### Kalman retuning (`kf1` → `kf2`)
The original Kalman over-trusted the constant-velocity model and undershot sharp
turns. Raising process noise (`q` 1 → 5) and seeding initial velocity fixed the
undershoot:

| Log | kf1 reach | kf2 reach |
|-----|-----------|-----------|
| circle | 87.1% | 104.3% |
| uturn2 | 100.0% | 100.0% |
| flick | 81.1% | 101.1% |

Tradeoff: `kf2` adds jitter (tracking a reversal means following the
measurement). See [kf1_vs_kf2](../kf1_vs_kf2.md).

### ML cannot predict mouse movement
- Regressing `y` on `x` is ill-posed for non-monotonic paths (circle R²≈0.04,
  flick R²≈0.00) — a path is not a function of `x`.
- Parametric fitting on `t` reconstructs any path (R²≈1.0) but that is
  interpolation of a recorded curve, not prediction, and is scored on training
  data.
- Adding `Magnitude`/`Direction` as features did not help and hurt flick
  (R²x 0.84 → 0.69): they are the path derivative, and a memoryless regressor
  cannot integrate them into position.

Full write-up: [ml_analysis](../ml_analysis.md).
